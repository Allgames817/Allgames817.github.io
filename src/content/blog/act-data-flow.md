理解一个策略模型，可以先暂时放下实现细节，从两个问题开始：它接收什么，又输出什么？这篇示例笔记用一条简化的数据流来组织阅读，而不讨论尚未提供的实验结果。

## 从输入与输出开始

在概念层面，策略把当前观测映射为动作。阅读 ACT 时，可以把“动作块”作为理解输出的入口：一次预测涉及一段动作序列，而不只关注单个时间点。

- **观测**：模型能够获得哪些信息？
- **表示**：不同输入怎样转成模型使用的特征？
- **动作块**：输出的时间范围如何定义？

下面是一段用于说明输入输出关系的伪代码，没有绑定具体复现仓库或控制频率。

```python
# 概念伪代码，不是实际机器人控制程序
observation = read_observation()
action_chunk = policy.predict(observation)
record_for_inspection(observation=observation, predicted_action_sequence=action_chunk)
```

## 把模型与控制过程分开看

模型输出与机器人执行之间还有接口。阅读代码时，应区分训练的数据组织、推理得到的预测，以及控制端如何消费这些预测。它们相关，但不是同一个问题。

> 一张数据流图的价值，是帮助发现尚未弄清楚的接口，而不是代替对实现的检查。

### 一个简化的记号

用 $o_t$ 表示当前观测，用 $k$ 表示动作块的长度，可以将概念关系写成：

$$
\hat{a}_{t:t+k-1} = \pi_\theta(o_t)
$$

这个式子只说明输入输出关系，省略了具体条件、训练过程与执行策略。它也用于展示本网站的数学公式排版。

## 怎样组织一份复现记录

后续真实记录可以围绕三个层次展开：先描述环境和输入，再明确实现与原文的对应关系，最后呈现有条件、有边界的结果。

| 记录部分 | 应当回答的问题 |
| --- | --- |
| 数据 | 来源、结构和预处理是什么？ |
| 实现 | 采用哪个版本，修改了哪些地方？ |
| 评估 | 在什么条件下，用什么方式评价？ |
